# Чек-лист запуска и ограничения

## Ручные действия (без них магазин не заработает)

1. GitHub → Settings → Pages → Source: GitHub Actions; Variables `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY`.
2. Supabase: проект, `supabase db push`, секреты, `supabase functions deploy …` ([supabase.md](supabase.md)).
   Проверить, что JWT, выпущенный `auth-telegram`, принимается API (настройка JWT secret).
3. Telegram: бот, `/newapp`, `npm run telegram:setup`, чат менеджеров, `manager_chat_id` ([telegram.md](telegram.md)).
4. Владелец: открыть Mini App, `select public.bootstrap_owner(<id>)` ([admin.md](admin.md)).
5. Настройки магазина: реквизиты, оферта, политика ПДн, возврат, доставка, ссылки на канал/бота/менеджера.
6. Удалить демо-данные (или не применять seed в production).
7. Поставщики → чек-лист; товары → проверка ассортимента → публикация.
8. Юридические вопросы: оферта, политика ПДн, уведомление РКН, локализация ПДн, чеки, маркировка ([compliance.md](compliance.md)).
9. Оплата — когда выбран провайдер ([payments.md](payments.md)). До этого работают заявки и офлайн-оплата.
10. pg_cron для обезличивания ПДн.

## Известные ограничения MVP

- Справочники/виджеты ПВЗ и расчёт стоимости перевозчиков не подключены: адаптеры `ShippingProvider` работают в
  ручном режиме, пункт выдачи вводится вручную и подтверждается менеджером. Заказы перевозчикам не передаются.
- Поставщик без API: остатки — ручное подтверждение и CSV-импорт. Бронирования у поставщика нет.
- Товар не резервируется при заявке; одновременные заявки на последнюю единицу разрешаются менеджером.
- ЮKassa-адаптер не проверен на реальном API (нет credentials); mock — только development.
- Кодов маркировки «Честный знак» и интеграции с онлайн-кассой вне провайдера нет.
- Нет полнотекстового поиска с морфологией (поиск по подстроке названия и артикула).
- Таблица размеров хранится как JSON (`size_chart`), редактора таблицы в админке нет (заполняется через SQL/API).
- Счётчик ограничения частоты — в Postgres; для высокой нагрузки стоит вынести в Redis/KV.
- Админка работает внутри Telegram (в т.ч. Desktop); отдельного входа из обычного браузера нет.
- e2e-сценарий использует эмулятор REST поверх PGlite и имитацию Telegram/Edge Functions; реальные Supabase и
  Telegram в автотестах не задействованы.
