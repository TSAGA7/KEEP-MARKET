# Тесты

| Набор | Что проверяет | Как запускать |
|---|---|---|
| `tests/db/security.test.ts` | RLS: аноним/покупатель/менеджер; закупочные цены скрыты; самоповышение роли; один владелец; bootstrap только service_role; админ-RPC без прав блокируются; чужие заказы; контакты только через функцию с журналом; неизменяемость аудита | `npm run test:db` |
| `tests/db/orders.test.ts` | серверный расчёт суммы; идемпотентность; расхождение цены; снятый с публикации товар; нулевой/недостаточный остаток; неактуальный остаток; товар без проверки; валидация доставки и ПДн; недопустимые переходы статусов; `paid` без платежа; полный workflow; отмена без фиктивных платежей | `npm run test:db` |
| `tests/db/payments.test.ts` | платёж только для подтверждённого заказа; повторный webhook; регрессия статуса; отказ; несовпадение суммы; возвраты (частичный/полный, лимит, права); офлайн-оплата | `npm run test:db` |
| `tests/db/catalog.test.ts` | блокировка публикации непроверенного товара; юр. поля только через проверку; чек-лист; снятие с публикации; поиск/фильтры/сортировка; некорректный прайс; применение и откат импорта | `npm run test:db` |
| `tests/unit/*` | подпись initData (подделка, чужой бот, срок), JWT, mock/ЮKassa адаптеры, чек со скидкой, корзина, схемы доставки, CSV, маскирование логов, совпадение статусов фронтенда и БД | `npm run test:unit` |
| `tests/e2e/run.mjs` | браузер 390×844: главная → каталог → товар (обязательный выбор варианта) → корзина → оформление (форма меняется по доставке, согласие) → заявка без оплаты, ссылка в бота без ПДн → админка → проверка наличия → подтверждение покупателем → поставщик → отправка; покупатель не открывает админку; тёмная тема; гость вне Telegram | `npm run test:e2e` |

Интеграционные тесты применяют настоящие миграции к Postgres 16 (PGlite, WASM) с ролями `anon/authenticated/service_role`
и `auth.uid()`, как в Supabase. Реальные банковские карты и платежи в тестах не используются.
