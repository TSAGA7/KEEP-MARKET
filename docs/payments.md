# Оплата

## Принципы

- При нажатии «Заказать» деньги **не** списываются. Платёж создаётся только для заказа в статусе `confirmed`
  (или позже до отправки), с согласованным способом `online` и известной стоимостью доставки.
- Сумма берётся из БД; клиент её не передаёт.
- «Оплачено» выставляется только по проверенному уведомлению провайдера. Переход на страницу оплаты и возврат
  пользователя оттуда оплатой не считаются: после возврата приложение ждёт подтверждения сервера.
- Повторные уведомления безопасны (`payment_events UNIQUE(provider, event_key)`), запоздавшие не откатывают
  успешный платёж, несовпадение суммы переводит заказ в «Проблема».
- Данные карт не проходят через наш сервер и не хранятся.

## Архитектура

`supabase/functions/_shared/domain/payments.ts`:

- `PaymentProvider` — интерфейс: `createPayment`, `verifyWebhook`, `createRefund`;
- `MockPaymentProvider` — только development (`APP_ENV=development`, `PAYMENT_PROVIDER=mock`), уведомления подписаны
  HMAC; в production фабрика бросает ошибку `MOCK_PROVIDER_FORBIDDEN_IN_PRODUCTION`;
- `YooKassaProvider` — готовый адаптер ЮKassa: создание платежа с ключом идемпотентности, данные чека (54-ФЗ),
  проверка уведомления **повторным запросом статуса в API** (тело уведомления не доверенное) и опционально по IP,
  возвраты. Протестирован на заглушках сети; перед запуском проверьте на тестовом магазине ЮKassa.

Edge Functions: `payment-create`, `payment-webhook`, `payment-refund`, `payment-mock-simulate` (dev).

## Выбор провайдера

Подключайте провайдера только после проверки, что он: работает с вашей формой бизнеса (ИП/ООО/самозанятый),
допускает ваш ассортимент и модель дропшиппинга, умеет формировать чеки по 54-ФЗ (или у вас есть своя онлайн-касса),
поддерживает возвраты по API. Решение о применимости 54-ФЗ, НДС и маркировки принимайте с бухгалтером.

## Подключение ЮKassa (пример)

1. Договор с ЮKassa, тестовый магазин. Получите `shopId` и секретный ключ.
2. Секреты: `PAYMENT_PROVIDER=yookassa`, `YOOKASSA_SHOP_ID`, `YOOKASSA_SECRET_KEY`, при чеках через ЮKassa —
   `YOOKASSA_SEND_RECEIPT=true` и `YOOKASSA_VAT_CODE` (по согласованию с бухгалтером).
3. Личный кабинет ЮKassa → HTTP-уведомления: `https://<ref>.supabase.co/functions/v1/payment-webhook`, события
   `payment.succeeded`, `payment.canceled`, `refund.succeeded`.
4. Опционально `YOOKASSA_ALLOWED_IPS` — актуальный список IP уведомлений из документации ЮKassa.
5. `supabase functions deploy payment-create payment-webhook payment-refund`.
6. Владелец: Настройки → `online_payment_enabled = true`, `payment_methods` — офлайн-способы, `require_payment_before_supplier`.
7. Проверка на тестовом магазине: заказ → подтверждение → «Оплатить онлайн» → тестовая карта ЮKassa →
   заказ получает «Оплачен» только после уведомления; повторите уведомление — двойной обработки нет; возврат.

Другой провайдер: реализуйте `PaymentProvider` в `domain/payments.ts` и добавьте ветку в `createPaymentProvider`.
Корзина, заказы и SQL менять не нужно.

## Тестовый сценарий (development)

`APP_ENV=development`, `PAYMENT_PROVIDER=mock`, `MOCK_PAYMENT_SECRET`, `MOCK_CHECKOUT_URL=http://localhost:5173/dev/mock-payment`,
во frontend `VITE_ENABLE_MOCK_PAYMENT=true`. Страница тестовой оплаты отправляет подписанное уведомление через
`payment-mock-simulate` → та же проверка и обработка, что и у настоящего webhook.

## Офлайн-оплата и возвраты

- Перевод/оплата при получении: владелец/администратор фиксирует фактически полученную сумму в карточке заказа (журнал).
- Возврат: карточка заказа → «Возврат». Для онлайн-платежа запрос уходит провайдеру; для офлайн — сотрудник
  подтверждает, что деньги уже возвращены переводом. Отменить оплаченный заказ без возврата нельзя.
