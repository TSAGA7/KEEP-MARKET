# Ассортимент, права потребителей, персональные данные

> Это технические меры и чек-листы, а не юридическое заключение. Документы и сценарии нужно проверить с юристом
> с учётом фактической модели бизнеса.

## Ассортимент

> С версии миграции 0012 юридическая проверка товаров и проверка товарных знаков **отключены по решению владельца**:
> публикация требует только категорию, цену, фото и вариант. Ответственность за законность ассортимента
> (товарные знаки, документы, маркировка) остаётся на магазине. Ниже — описание прежнего механизма для справки.

Магазин не поддерживает продажу контрафакта. В системе:

- товар публикуется и оформляется в заказ только при `compliance_status = approved` и `trademark_review_status = approved`;
  новый товар всегда создаётся непроверенным, юридические поля меняются только функцией проверки;
- одобрение требует полного чек-листа: нет чужих товарных знаков и сходных обозначений; проверены упаковка, бирки,
  фурнитура; фото без чужих брендов; дизайн не копирует охраняемые промышленные образцы; описание, SEO и фильтры не
  создают ложного впечатления связи с другими брендами; есть документы поставщика;
- отзыв одобрения автоматически снимает товар с публикации;
- документы — в приватном хранилище, доступ owner/admin, подписанные ссылки на 2 минуты;
- поле «Бренд» — только собственный или независимый бренд поставщика.

Чек-лист поставщика (раздел «Поставщики»): проверка юрлица/ИП, договор, права на обозначения, декларации/сертификаты
где обязательны, маркировка «Честный знак» где применимо, условия возврата и брака.

## Покупатели (дистанционная торговля)

Заполнить в Настройках перед запуском: реквизиты продавца (`seller_info`), оферта (`offer_text`), политика обработки ПДн
(`privacy_policy_text`, версия `privacy_policy_version`), условия возврата (`return_policy`), информация о доставке,
часы поддержки. Тексты показываются покупателю как обычный текст. Формулировки не должны ограничивать права,
предусмотренные Законом «О защите прав потребителей» и правилами продажи товаров дистанционным способом.

## Персональные данные (152-ФЗ)

- Собираются только ФИО, телефон, e-mail (необязательно), адрес/ПВЗ; паспортные данные не запрашиваются и не принимаются.
- Согласие на обработку ПДн — обязательный чекбокс при оформлении; версия политики сохраняется в заказе и профиле.
- Контакты — отдельная таблица; сотрудники видят их только через функцию с записью в журнал; в уведомлениях ПДн нет.
- Поставщику передаётся только состав заказа и данные для отправки, без доступа к базе.
- Обезличивание контактов закрытых заказов по сроку `pd_retention_days` (pg_cron, см. supabase.md).
- **Требует решения владельца:** уведомление Роскомнадзора об обработке ПДн; размещение БД — 152-ФЗ требует первичной
  записи и хранения ПДн граждан РФ в базах на территории РФ. Облачный Supabase размещается за рубежом — до запуска
  оцените с юристом риски и варианты (self-hosted Supabase на российском хостинге и т.п.).

## Кассовые чеки и маркировка

- 54-ФЗ: при онлайн-оплате нужен чек. Адаптер ЮKassa умеет передавать данные чека (`YOOKASSA_SEND_RECEIPT`),
  но применимость, ставки НДС и признаки расчёта согласуйте с бухгалтером. Для офлайн-оплаты (курьер, перевод)
  чек оформляется вашей кассой вне системы.
- Обязательная маркировка («Честный знак») распространяется на часть одежды и обуви — проверяйте по каждой товарной
  группе; поля для кодов маркировки в MVP нет (см. ограничения).
